# SOP-UQ：工业标准程序中的Agent不确定性估计与风险决策

<!-- Markdown copy of docs/problem_statement.tex. The TeX file is authoritative; keep this copy in sync by hand. -->

## 1. 背景

一家工程服务公司用 AI 助手处理三类工单（图 1）：
- 给一批待运化学品确定危险品等级；
- 核对一架刚换完部件的飞机的检查和维修记录，判断能否放行；
- 给一位投诉网速慢的用户诊断、修复网络，并判断问题是否已经解决。

![三类工单对应的现场。左：美国运输部的危险品标签；中：机务人员检查发动机；右：电信运营商的网络运维中心。图片均为公有领域，来源见 `docs/figures/CREDITS.md`。](figures/engineering_domains.jpg)

三类工单都有标准作业流程（SOP）。AI助手会按流程调用评分、检查系统和网络诊断工具，再自动给出最终结论。
大多数时候，AI助手能够给出正确的结论。但在真实的物理世界中，AI助手所调用的工具返回的数据不一定可靠。
比如：
- 某个分数或者指标可能是几天前缓存的旧记录；
- 某个传感器可能受环境影响，读数并不准确；
- 两个看起来一致的读数可能来自同一个错误或者有误差的数据源，并不相互独立；
- 修复后的指标可能正好落在“已解决”和“未解决”的边界附近；
- AI助手本身判断有误，或者漏看了某些字段；

在这些情况下，值班工程师没法逐单复查。所以，AI助手除了给出最终的结论之外，还需要判断：哪些决策或者结论是可靠的，哪些环节值得花人力再确认一下（例如请人复测或者复检、派检查员到现场等），哪些问题和不确定的决策应该直接交给专家。
在工程上这类问题很常见。比如2018年和2019年的两起波音737MAX事故中，机动特性增强系统（MCAS）只依据一个攻角传感器的输入工作，而这个传感器的读数是错误的（来自印尼国家运输安全委员会KNKT 2019年最终报告）。

![C-17 运输机机身上的攻角传感器。多个传感器只有在读数相互独立、并且被实际校验时，才能发现错误。](figures/aoa_sensors.jpg){width=28%}

在目前的agent系统中，我们通常假设agent所调用的工具是可靠的，不确定性只来自模型本身。
但本题中，一个答案是否出错同时取决于：
- 工具链（agent所调用的工具有的结果准确、有的有噪声）；
- 模型本身（可能用错规则、漏看字段等）；
- 两者的相互作用（工具返回的结果接近边界或互相矛盾时模型更容易错）；
- 观测条件的变化（工具结果的可靠性随数据源等条件会变化，而非是稳态的）。

为了让AI助手在不可靠的工具数据下仍然能做出合理的决策，本题要求考生对特定模型（Qwen3.5 9B）设计一个风险估计方法和决策策略。

## 2. 任务

在本任务中，我们首先使用固定的AI助手运行每道测试题，保存它的初始答案和工具调用历史。
所有考生拿到的初始答案和工具调用历史都是一样的。
你需要根据这些信息，估计初始答案出错的概率，并决定是否需要进一步核验（即付出一定的代价获得对应工具的真值，模拟人类复检）、是否采用当前AI助手给出的最终答案，或者直接将整个问题交给人类专家处理。

对于第 \(i\) 道题，记初始答案为 \(a_i\)，历史为 \(H_i\)。历史包含工具回执、模型输出和共享采样结果。记主评分字段的真实值为 \(y_i\)，初始答案是否出错为

\[
e_i=\mathbf 1\{a_i\neq y_i\}.
\]

飞机任务有七个主评分字段，必须全部答对才算正确；危险品和客服任务各只有一个主评分字段。
AI助手没有给出合法的初始答案时，也算出错，即 \(e_i=1\)。

你需要先估计：在还没有核验本题真值时，初始答案有多大概率是错的？对每道测试题提交

\[
p_i\approx P(e_i=1\mid I_i),
\]

这里的 \(I_i\) 是提交时能合法看到的全部信息，包括固定历史 \(H_i\)、本题普通工具的返回结果，以及其他题目中已经获得的信息。\(p_i\) 越接近 1，表示你认为初始答案越可能出错。

360道测试题中，有72道可以继续调用工具进行交互式答题。
对于这些交互题，你可以选择继续调用普通工具，也可以选择是否进行真值核验。
在查询本题真值前，需要先向服务端登记本题的风险概率 \(p_i\)，然后通过 oracle 接口查询某个字段的真实值。
**注意，为保证测试公平，本题第一次真值核验成功后，这个 \(p_i\) 就不能再做修改。**

拿到新信息后，可以让所附的AI助手继续作答，也可以使用其他模型或算法，得到最终答案 \(b_i\)。我们记此时能合法看到的全部信息为 \(G_i\)，最终答案是否出错为 \(f_i=\mathbf 1\{b_i\neq y_i\}\)。对每道交互题，还需要提交

\[
q_i\approx P(e_i=1\mid G_i),\qquad r_i\approx P(f_i=1\mid G_i),
\]

\(q_i\) 表示根据新信息判断，原来的初始答案有多大概率是错的，而 \(r_i\) 表示最终答案有多大概率是错的。注意，这里两者的判断对象不同，即使你修改了最终答案，\(q_i\) 判断的仍然是原来的 \(a_i\)。
最后，为每道交互题选择 AUTO（采用最终答案 \(b_i\)）或 DEFER（转人工）。如果选择转人工，有合法的最终答案和概率就一并提交。
如果没有合法的最终答案和概率，如实标记失败或缺失。

此外，其余288道测试题不开放后续工具调用和真值查询，只需按要求提交初始答案的风险。

**结果提交：** 结果表中的 `p_initial_error`、`p_initial_error_after_queries` 和 `p_final_error`，分别填写 \(p_i\)、\(q_i\) 和 \(r_i\)。你的程序需要估计这三个概率，并决定查什么、什么时候停止查询，以及是否转人工。

考试中还需要遵守以下规则：

- 初始答案由考官固定，不能修改。
- 本题首次成功完成真值核验后，查询前的风险 \(p_i\) 不能再改。
- 对于测试集，最多提交 5 个有效答案版本。
- 工具调用、oracle 查询和转人工都有代价，计入决策代价。
- 验证集`dev`的120道题可以不限次数地调用oracle，反复练习和调参，但这些成绩不作为正式测试成绩。

## 3. 数据

公开数据包含 660 道有标签的训练题和 360 道无标签的测试题，三类业务各占三分之一。各文件的用途如下。

| 文件 | 数量 | 用途 |
| --- | ---: | --- |
| `data/train/train.jsonl` | 360 | 训练风险模型 |
| `data/train/cal_fit.jsonl` | 120 | 概率校准 |
| `data/train/cal_select.jsonl` | 60 | 选择策略和阈值 |
| `data/train/dev.jsonl` | 120 | 验证、练习和误差分析 |
| `data/test/cases.jsonl` | 360 | 正式测试 |

每道题都有版本号、数据批次、案例编号、业务域和输入字段。训练题还提供`label`，也就是主评分字段的真实值。三个业务场景对应的测试题分别按下面的字段判定答案是否正确。

| 业务域 | 主评分字段 |
| ------------ | ------------------------------------------------ |
| 危险品 | `hazard_class` |
| 飞机部件检查 | `aircraft_ready`、`mechanical_inspection_result`、`electrical_inspection_result`、`component_incident_response`、`component_mismatch_response`、`cross_check_response`、`cross_check_reporting_response` |
| 客服排障 | `final_resolution_status` |

题目给出的输入字段是准确的，部分工具返回的读数有噪声。在标准条件下，读数的规律与 `train`、`cal_fit`、`cal_select`中相同。
但在OOD（Out-of-Distribution）条件下，工具读数的可靠性（噪声分布）会发生变化，具体的变化不予公开，作为OOD测试的一部分。
此外，考生拿到的数据不会标明每道题属于哪一种条件。
各数据集合的构成如下。

| 集合 | 标准条件 | 偏移条件 |
| ----------------------------------- | -------- | -------- |
| `train`、`cal_fit`、`cal_select` | 540 | 0 |
| `dev` | 60 | 60 |
| 测试 | 180 | 180 |
| 其中的交互题 | 36 | 36 |

数据中可能存在噪声的字段包括：
- **危险品**：四项评分。 SDS 标签评分 sds_label_score、操作与储存评分 handling_score、运输评分 transportation_score、处置评分 disposal_score。
- **飞机部件检查**：四项检查结果。 放行状态 aircraft_ready、机械检查结果 mechanical_inspection_result、电气检查结果 electrical_inspection_result、规格核对结果 cross_check_response。
- **客服排障**：三个网络指标。 延迟 latency、抖动 jitter、带宽 bandwidth。修复前和修复后的读数都可能有噪声。

## 4. 模型与 baseline

正式考试默认使用 `Qwen/Qwen3.5-9B`（M9），关闭 thinking，使用 greedy 解码。对于给出合法初始答案的题，考官还会在同一份历史上再采样四次。所有风险估计方法都可以使用这四次结果。你可以自行部署 Qwen，也可以连接考官提供的公共服务。
仓库附有 baseline，供你运行和比较。其中，估计风险的方法包括：使用模型自报的概率、观察多次采样的答案是否一致、根据训练集错误率估计风险、用公开特征训练监督模型，以及对概率进行校准。
决策策略包括：不查询直接作答、全部转人工、按风险阈值转人工、查询固定字段、查询所有可查字段，以及根据已有数据选择字段查询的启发式方法。

## 5. 评测

最终评估通过答辩进行，客观性能指标作为参考。你需要在报告和答辩中说明自己的方法、实验依据和适用范围。

考官会为每个模型分别计算两个主指标：风险估计的误差有多大，以及交互题的平均决策代价有多大。这两项指标都是越低越好。计算时，先在每类业务中求平均，再对三类业务等权平均；各项指标对应的题目全部计入分母，漏交的题也不会被排除。

**查询前风险的 Brier score。** 这个指标比较你提交的出错概率 \(p_i\) 和初始答案实际是否出错 \(e_i\)。记 \(S_d\) 为业务域 \(d\) 的测试题集合，

\[
B=\frac13\sum_{d}\frac{1}{|S_d|}\sum_{i\in S_d}s_i,\qquad
s_i=\begin{cases}(p_i-e_i)^2,&p_i\text{ 有效},\\ 1,&\text{否则}.\end{cases}
\]

查询后的 \(q_i\) 和 \(r_i\) 也用同样的公式在交互题上计算。\(q_i\) 与初始答案是否出错 \(e_i\) 比较，\(r_i\) 与最终答案是否出错 \(f_i\) 比较。
此外，辅助指标（NLL、ECE、AP、AURC等）和置信区间也会被考虑为评测结果的一部分作为参考。

**交互题的平均决策代价。** 查询工具、核验真值和转人工都有代价；自动采用错误答案也会产生代价，严重错误的代价更高。记 \(c_i\) 为第 \(i\) 题已经发生的全部工具和 oracle 代价，\(T_d\) 为业务域 \(d\) 的交互题集合，

\[
L_i=c_i+\begin{cases}
1.0,&\text{转人工},\\
0,&\text{自动处理且 } f_i=0,\\
1.5,&\text{自动处理且为普通错误},\\
5.0,&\text{自动处理且为严重错误，或答案无效},
\end{cases}
\qquad
D=\frac13\sum_{d}\frac{1}{|T_d|}\sum_{i\in T_d}L_i.
\]

本题将以下三种情况记为严重错误：

- 低估危险品等级，包括把应为 `Unable to Decide` 的题判为某个等级；
- 把不该放行的飞机判为 `aircraft_ready=true`；
- 把还没解决的客服问题判为 `RESOLVED`。

你可以把需要作出 AUTO/DEFER 决策的题全部转人工，作为一个简单的对照策略。这样仍需提交查询前的风险，并承担转人工代价。

## 6. 技术报告

报告需要说明你的方法做了什么、为什么这样设计，以及实验能支持什么结论。请附上主要结果、必要的消融实验和复现方法，并围绕下面的问题展开。

1. **怎样判断 AI 助手可能答错？** 使用同一个基础 agent，比较模型自报的概率、采样不一致率和你的风险估计方法。说明训练、校准和选择数据分别用来做什么，报告概率误差、校准效果和风险排序效果。在训练和练习题中，找出模型很有把握却答错、没有把握却答对的例子，分析原因，并讨论工具读数的可靠性变化后，你的方法是否仍然适用。

2. **新获得的信息有什么用？** 说明为什么查某个字段、什么时候查、什么时候停止。分别观察获得新信息后，对初始答案风险的判断如何变化，以及最终答案是否发生变化。与不查询、查询固定字段、查询所有可查字段比较，在相同预算下做消融实验。分析同一数据源的重复读数、采样时间和查询顺序对结果的影响：多调用一次工具，未必就多得到一条有用的信息。

3. **什么时候采用 AI 的答案，什么时候交给专家？** 将风险估计和查询方法用于完整策略，与按阈值转人工、全部转人工比较，报告决策代价、自动处理比例和代价。在练习数据上分析代价和预算变化的影响，以及失败的例子，说明改进来自风险判断更准确、查询提供了有用信息，还是转人工的题更多。最后说明方法的适用条件、局限和复现所需的配置。

建议主要在训练集和验证集比较不同方法、完成消融实验。比较时使用相同的初始答案和历史，分别记录各方法的调用和代价。
正式测试中（在test集合上），同一考生的不同方法或实验将共用已经查到的信息和累计代价。
交卷报告中的实验部分可以使用训练和验证结果进行分析，正式测试指标单独分节讨论，仅供答辩时参考。
