# SOP-UQ：工具证据下的错误概率估计与核验决策

修订日期：2026-10-12。主数据格式为 2.1；正式考试采用本题面的逐题风险封存与五次提交规则。历史参考轨迹、校准器和成绩须核对接口、配置及实现版本，不能直接混用。

## 1. 背景

**一个夜班。** 凌晨两点，一家工程服务公司的调度台上，AI 助手正在同时处理三类工单（图 1）。仓库要发运一批化学品，需要按规则确定危险品等级；机库里一架飞机刚换完部件，早上七点要起飞，需要核对行政和维修记录上的放行条件；客服系统里有用户投诉网络卡顿，需要按流程诊断、修复，并判断问题是否已经解决。这里的飞机任务不包含完整的物理适航检查。

![三类工单对应的现场。左：美国运输部的危险品标签；中：机务人员检查发动机；右：电信运营商的网络运维中心。图片均为公有领域，来源见 `docs/figures/CREDITS.md`。](figures/engineering_domains.jpg){width=100%}

这三件事都有成文的标准作业流程（SOP），步骤明确，工具齐全。AI 助手按流程逐步调用系统：查询评分服务、读取检查记录、运行网络诊断，然后给出结论。大多数时候它是对的。麻烦在剩下的那一部分：评分服务返回的某个分数可能是几天前存下的旧记录；检查系统里两个看似互相印证的读数，可能出自同一个源头；修复后的网络指标，可能恰好落在"已解决"和"需升级"的分界附近。这些情况下，AI 助手给出的答案依然格式工整，自报的把握依然很高。

值班工程师只有一位，不可能把每张工单都重做一遍，也不能不加区分地全部放行。真正需要的是一份判断：哪些答案可以直接采用；哪些值得花钱再核实一个关键事实，比如请实验室复测、派检查员去机库确认、调取网络的权威测量；哪些应该直接交给专家。这就是本题要回答的问题。

**为什么这在工程上重要。** 把语言模型 agent 接入工程流程后，难点往往不在于它平均答对多少，而在于能否在交付之前认出它可能答错的那些单子。

- **错误的代价不对称。** 低估危险品等级可能酿成运输事故；把不具备条件的飞机签发放行，后果远比推迟一个航班严重；把没解决的故障标成已解决，问题会被掩盖。相比之下，转给专家只是多花一些时间和人力。
- **读数并不总是可靠，多个读数也未必独立。** 2018 年 10 月的印尼狮航 610 航班和 2019 年 3 月的埃塞俄比亚航空 302 航班两起波音 737 MAX 事故中，机动特性增强系统（MCAS）只依据一个攻角传感器的输入工作，而这个传感器的读数是错误的；印尼国家运输安全委员会（KNKT）2019 年的最终报告专门讨论了这种对单一传感器的依赖。飞机上通常装有多个攻角传感器（图 2），但冗余能否降低风险，取决于系统是否真正比较了相互独立的读数。反复读取同一个出错的来源，并不能发现它的错误。

![C-17 运输机机身上的攻角传感器。冗余传感器只有在读数相互独立、并被实际比较时才能发现错误。图片为公有领域，来源见 `docs/figures/CREDITS.md`。](figures/aoa_sensors.jpg){width=28%}

- **核验有成本，模型往往不能改。** 复测、现场检查和调取权威记录都要花钱花时间。企业部署的通常是供应商提供的固定模型，无法为每个场景重新训练，能改进的是模型外面的一层：估计风险，决定核验什么、何时转人工。
- **现场条件会变化。** 新的仓库、老化的传感器、不同的数据系统，都会让现场读数的可靠性与开发时不同，而开发时能拿到的带标签数据大多来自熟悉的条件。

**从 agent 不确定性看这个问题。** 讨论 agent 时，通常默认工具可靠：工具返回什么，agent 就把它当作事实，不确定性只来自模型本身。真实工程中的工具并非如此。在本题中，一个答案是否出错至少受以下四类不确定性影响。它们相互耦合，也不会在不同案例和条件下保持不变。

1. **工具链的不确定性。** 处理一张工单要依次调用多种工具，它们的可靠程度不同。账户状态、报告服务等返回的是如实的业务记录；评分、检查结论和网络指标的读数则可能与真实状态不一致，第 3 节列出了全部可能含噪声的字段。这些工具前后相连：前一步的读数决定下一步调用什么工具、传入什么参数、进入哪条业务分支，一个错误读数可以带偏整条后续路径，后面的步骤即使调用的是可靠工具，也建立在错误的前提上。读数是否可靠，还取决于从哪个来源、以什么方式、在哪个业务阶段获取；同一来源的重复读数不能当作相互独立的证据。
2. **模型自身的预测不确定性。** 即使读数全部正确，模型也可能用错规则，例如算错阈值、漏看某个字段、走错分支；也可能没有调用完必要的工具就给出答案，或者输出不合法。模型自报的把握和多次采样的一致程度只能反映其中一部分。共享采样都基于同一份已经取得的证据，证据本身有误时，几次采样可能一致地给出同一个错误答案。
3. **证据与模型的耦合。** 上述两类不确定性不是简单叠加。读数是否贴近判定边界、是否缺失、是否相互矛盾，都会改变模型出错的概率；反过来，模型决定调用哪些工具、以什么方式调用，也决定了它能拿到哪些证据。核验之后，模型读入新证据重新作答，可能纠正原来的错误，也可能把对的改错，因此原答案和新答案的出错概率需要分别估计。
4. **不确定性随条件变化。** 读数的可靠性在不同来源、不同业务阶段之间不同，在标准与偏移观测条件之间也不同。训练、校准和选择划分只含标准条件，公开的验证集另含偏移案例及其标签。模型的出错率同样因案例而异：贴近边界、证据不全或经过续跑的案例，出错方式与普通案例不同。核验策略本身也会改变核验后历史的分布，所以核验后的风险估计必须与所用策略匹配。用一个固定的出错率，或者假设训练时的读数规律在测试时原样成立，都无法可靠地估计风险。

本题要求的风险估计，就是在这些不确定性同时存在时，判断一个具体答案出错的概率；核验与转人工策略则决定花多少代价、去减少其中哪一部分。

**题目如何对应这些问题。** 本题把上述情境抽象为可复现的评测。

| 工程中的情况 | 题目中的设定 |
| ---------------------------------- | -------------------------------------------------------- |
| 需要比较对同一批初始答案的风险判断 | 考官固定 Qwen 初始答案及证据；考生自行实现风险估计与后续求解、核验和转人工策略 |
| 预测要先于本题真值核验 | 每道测试题第一次 oracle 返回前封存本题风险，正式成绩在整场考试交卷后统一公布 |
| 记录可能过时，读数可能出错，多个读数可能同源 | 部分字段的读数可能含噪声；不同请求模式访问不同来源，回执给出来源、记录编号和采样时间 |
| 请实验室复测、派检查员确认 | oracle 返回单个字段的真实值，每次费用 0.10 |
| 交给专家处理 | 转人工，代价 0.50 |
| 错误后果有轻有重 | 普通错误代价 1，严重错误代价 5 |
| 开发条件与现场条件不同 | `train`、`cal_fit`、`cal_select` 为标准条件；`dev` 和测试各有一半偏移案例，不标注单例条件 |
| 工程师可以从处理过的工单中学习 | 允许跨题分析与在线调整；已经核验的测试题不能回改其核验前风险 |
| 事后需要审计 | 服务端记录全部调用与费用，初始答案由考官固定 |

本题在危险品分类、飞机部件检查和客服排障三个模拟业务中研究两个问题：如何估计一个固定 agent 的答案出错的概率，以及何时付费核验事实、何时采用模型答案、何时转人工。三个业务沿用所附 SOP 与工具接口，判定以本题公开的业务规则为准。全部任务都在教学模拟环境中进行，数据为合成数据，结果不构成真实的危险品分类、适航或维修结论；上述故事和事故只用于说明问题的工程背景。

## 2. 问题定义

**初始答案。** 对案例 \(i\)，记主评分字段的真实值为 \(y_i\)。考官用固定 agent 运行每个测试案例，得到初始答案 \(a_i\) 及其可见历史 \(H_i\)，其中包括工具回执、模型输出和共享采样。所有考生面对同一组 \((a_i, H_i)\)。初始错误定义为

\[
e_i=\mathbf 1\{a_i\neq y_i\}.
\]

飞机任务须七个主字段全部正确才算正确，其余两个任务各有一个主字段。没有合法答案时 \(e_i=1\)。

**第一阶段：核验前风险。** 对每个测试案例提交

\[
p_i\approx P(e_i=1\mid I_i).
\]

\(I_i\) 是本次风险预测时合法可见的信息，包括固定历史 \(H_i\)、本题已经取得的普通工具记录，以及此前合法取得的其他案例信息。允许跨题分析和在线调整，不要求先把整张试卷的风险全部封存。

本题第一次 oracle 返回之前，必须先封存本题的 \(p_i\) 或明确的失败、缺失状态；核验后不能回改。若正式评测包含多个初始模型，同一业务案例的各模型风险都须先封存，不能换模型绕过。未查询 oracle 的题可以在后续答案版本中修订 \(p_i\)，最终取最后有效版本。核验前风险仍使用协议字段 `p_initial_error`，不表示所有方法只能依据固定 \(H_i\)。

**第二阶段：核验与决策。** 交互案例可以调用普通工具，并在本题风险封存后调用 oracle。考生可使用所附 agent 续跑，也可选择其他模型或算法处理合法证据，给出最终答案 \(b_i\)。此时合法可见的信息记为 \(G_i\)，最终错误为 \(f_i=\mathbf 1\{b_i\neq y_i\}\)。对每个交互案例提交

\[
q_i\approx P(e_i=1\mid G_i),\qquad r_i\approx P(f_i=1\mid G_i),
\]

以及决策 AUTO（采用 \(b_i\)）或 DEFER（转人工）。\(q_i\) 评估的仍是初始答案，其目标是 \(e_i\) 而不是 \(f_i\)。选择 DEFER 时仍须提交 \(b_i\) 和 \(r_i\)，供影子评测使用。结果表中，\(p_i\)、\(q_i\)、\(r_i\) 依次对应 `p_initial_error`、`p_initial_error_after_queries` 和 `p_final_error`。

你需要实现给出 \(p_i\)、\(q_i\)、\(r_i\) 的风险估计器，以及决定核验什么、何时停止和是否转人工的策略。评分见第 5 节。

**规则与边界。**

- 正式测试的初始答案、证据和共享采样由考官固定。服务会核对提交的初始答案与固定记录一致；没有可信的初始记录时，服务不开启正式测试。
- 允许跨题分析、在线调整参数，以及自行选择后续模型或算法。方法和配置变化须记录，便于复现；固定的初始答案及其证据不能改写。
- 测试集的核验记录、费用和额度绑定同一考生与试卷。换方法、换后续模型、新建运行或重交答案都不能重置。只有原定 72 道交互题允许 oracle，其余 288 道不开放核验真值。
- 每名考生最多提交五个不同的有效完整答案版本。有效指协议合法，不代表答对；网络重传同一逻辑答案不重复计数，无效包不占有效次数。前四次可以继续修改和查询，第五次有效提交自动交卷，也可以提前交卷。
- 已核验题的事前风险取唯一封存记录，未核验题的风险及交互题的终局答案取最后有效版本。每版保留独立历史，不能用旧版本逃避后来发生的核验费用；正式测试期间只确认收件，整场交卷后统一公布成绩。
- 验证集为 `data/train/dev.jsonl` 的 120 道题。允许无限 oracle 核验、反复练习、即时评估和调参，不要求先封存风险，不占测试提交次数或额度。验证权限不能用于读取测试案例。
- 不得越权获取测试答案、读取他人的核验记录或伪造调用、回执与结果来源。自己用模型或算法算出的答案和概率合法。无法得到合法答案或有效概率时，如实提交失败或缺失状态。
- 所有核验须使用服务允许的字段和业务阶段；请求只包含工具 schema 规定的参数。公开报告不得披露测试核验真值、服务凭据或他人的材料，私有复现材料单独交给考官。

**费用与预算。**

| 操作 | 每次费用 |
| ------------------------------------------------ | -------- |
| 普通工具调用 | 0.01 |
| 以 `independent` 模式读取可能含噪声的字段（第 3 节） | 0.03 |
| oracle 核验一个字段 | 0.10 |
| 转人工（DEFER） | 0.50 |

正式测试每个案例的工具与 oracle 费用合计不超过 2.00，其中普通工具至多 24 次，oracle 至多 16 次；初始阶段已经发生的费用计入总额。所有方法和提交版本共用这份账单，最终计入交卷时的实际累计费用。网络重试同一请求不重复计费，新业务请求照常计费；本人已取得的事实可以从历史免费读回。

验证集不设 oracle 核验次数、核验费用或反复练习总次数上限。名义费用仍可记录用于比较策略，但不扣测试余额，也不能阻断后续诊断、维修和核验；需要新练习时可重开验证环境。字段、身份归属和业务阶段仍须符合接口约定。

默认测试预算 2.00 是资源保护上限，对现有有效核验路径一般不构成约束，不能据此声称验证了稀缺预算下的决策能力。研究预算约束时，可使用 0.50 或 1.00 的公开配置，重新采集相同条件的参考轨迹和校准数据，并单独报告。

**交付内容。** 可运行代码、配置与训练产物，由所提供客户端生成的 `submission.zip`（含 `manifest.json` 和 `results.csv`），以及 technical report。初始答案和已封存的风险必须与服务记录一致，终局答案和风险须对应本版证据；费用和调用次数以服务账本为准。公开报告与给考官的私有复现材料分开，运行和提交命令见项目 README。

## 3. 数据与工具观测

**数据文件。** 公开数据包含 660 个有标签的训练池案例和 360 个无标签的测试案例，三个业务域各占三分之一。

| 文件 | 数量 | 用途 |
| --- | ---: | --- |
| `data/train/train.jsonl` | 360 | 拟合风险模型 |
| `data/train/cal_fit.jsonl` | 120 | 概率校准 |
| `data/train/cal_select.jsonl` | 60 | 策略与阈值选择 |
| `data/train/dev.jsonl` | 120 | 验证、无限核验与误差分析 |
| `data/test/cases.jsonl` | 360 | 正式测试输入 |

每个案例包含版本号、数据批次、案例编号、业务域和公开输入；训练池案例另有 `label`（主评分字段的真实值）和所属划分。案例编号只用于关联，没有业务含义。训练池和测试都不提供真实业务状态。各业务域的主评分字段如下。

| 业务域 | 主评分字段 |
| ------------ | ------------------------------------------------ |
| 危险品 | `hazard_class` |
| 飞机部件检查 | `aircraft_ready`、`mechanical_inspection_result`、`electrical_inspection_result`、`component_incident_response`、`component_mismatch_response`、`cross_check_response`、`cross_check_reporting_response` |
| 客服排障 | `final_resolution_status` |

**可能含噪声的字段。** 公开输入是准确的业务记录。工具返回中只有下表字段的读数可能与真实状态不一致，其余返回都如实反映业务记录。oracle 只核验这些字段，每次返回一个字段在指定阶段的真实值；危险品的四个分数在 oracle 中分别写作 `sds`、`handling`、`transportation` 和 `disposal`。客服须先调用 `performTechnicalDiagnostics` 才能核验 `pre_repair` 阶段，完成 `executeTroubleshooting` 后才能核验 `post_repair` 阶段。

| 业务域 | 可能含噪声的字段（返回该字段的工具） |
| ------------ | ------------------------------------------------ |
| 危险品 | `sds_label_score`、`handling_score`、`transportation_score`、`disposal_score`（四个 `calculate_*_score` 工具） |
| 飞机部件检查 | `aircraft_ready`（`VerifyAircraftClearance`）、`mechanical_inspection_result`（`VerifyMechanicalComponents`）、`electrical_inspection_result`（`VerifyElectricalSystems`）、`cross_check_response`（`CrossCheckSpecifications`） |
| 客服排障 | `latency`、`jitter`、`bandwidth`（`performTechnicalDiagnostics` 与 `executeTroubleshooting` 返回的服务指标） |

**观测条件。** 每个案例有一个观测条件。它只影响上表字段的读数，不改变业务规则和标签的定义。标准条件下的读数规律与 `train`、`cal_fit`、`cal_select` 相同；偏移条件下，这些读数的可靠性有所变化，具体形式不公开，各偏移案例之间也不尽相同。公开 `dev` 中已有 60 道带标签的偏移题，不能把使用它们的方法说成从未接触偏移标签。数据不标注单个案例的条件。各集合的构成如下，每个集合中两类案例在三个业务域间平均分配。

| 集合 | 标准条件 | 偏移条件 |
| ----------------------------------- | -------- | -------- |
| `train`、`cal_fit`、`cal_select` | 540 | 0 |
| `dev` | 60 | 60 |
| 测试 | 180 | 180 |
| 其中的交互案例 | 36 | 36 |

**观测来源与请求模式。** 返回可能含噪声字段的工具可在请求中指定 `mode`。每个业务域有两个观测来源：`default`、`refresh` 和 `remeasure` 读取主来源，`independent` 读取第二来源。模式名描述读取路径，不保证统计独立。回执中的 `source_id` 标识来源，同一业务域的所有案例共用这两个标识；同一来源的读数共享该来源的特性，不能当作相互独立的证据。

| `mode` | 来源 | 费用 | 返回的记录 |
| -------------- | ---------- | ------ | ---------------------------------------------- |
| `default` | 主来源 | 0.01 | 可能是此前存储的较早记录；同一字段、同一阶段的重复请求总是返回同一条记录 |
| `refresh` | 主来源 | 0.01 | 不使用 `default` 的存储记录，但不保证返回本次新采样的记录。危险品分数和飞机的四个字段在每个来源、每个阶段只有一条当前记录，重复请求返回同一条；客服指标的重复请求可以得到新的读数，其中第一次请求与 `default` 未使用存储记录时的读数相同 |
| `remeasure` | 主来源 | 0.01 | 当前与 `refresh` 行为相同，两者按同一顺序编号：第 n 次 `remeasure` 与第 n 次 `refresh` 返回同一条记录 |
| `independent` | 第二来源 | 0.03 | 返回第二来源在本阶段的当前记录。危险品分数和飞机的四个字段每个阶段只有一条；客服指标从第二次请求起每次返回新的读数 |

其余工具不受 `mode` 影响，任何模式都按 0.01 计费。回执中的 `observation_id` 标识底层记录：两个读数的 `observation_id` 相同，说明是同一条记录，后一次读取没有带来新信息。`sampled_at` 是记录的采样时间，`observed_at` 是本次请求时的业务时间；`sampled_at` 早于 `observed_at`，说明返回的不是本次采样的记录。客服的诊断和排障一次返回三个指标，各指标的 `field`、`source_id`、`sampled_at` 和 `observation_id` 列在回执的 `observations` 中。

**其他说明。** SOP、工具说明、输出类型和业务规则随代码提供；每个案例实际可调用的工具及其参数以服务返回为准。工具的成功回执只表示该次调用完成，不代表模型的业务结论正确。客服的读数须按业务阶段解释，后一阶段的状态只有完成规定操作后才能读取。交互资格由服务返回；当前正式配置为每个模型 72 个交互案例，其余测试案例只评估初始风险。`challenge_data/` 另附 72 个边界案例，覆盖恰好达到、略低于或略高于阈值以及单项异常等情况；它们使用独立的数据版本，只用于检查规则实现，不计入主测试成绩。

主数据是合成数据。去重会改变生成参数所描述的比例；校准集和交互案例按业务分支覆盖选取，其中的比例不能解释为真实场景的发生率。危险品任务考察给定工具分数下的分类，不考察阅读真实 SDS 文档的能力；飞机的 `aircraft_ready` 只表示行政和维修记录上的放行结果，不是真实的适航结论。

## 4. 基础模型与 baseline

**模型。** 提供两个锁定的模型配置：M9 为 `Qwen/Qwen3.5-9B`，BF16 权重；M27 为 `Qwen/Qwen3.8-27B` 的指定 `UD-Q4_K_M` GGUF 制品。默认正式配置使用 M9，M27 用于考官另行配置的扩展评测，两者成绩分别报告，量化方式也属于配置的一部分。文件哈希、tokenizer、推理设置和运行方式见 `model_profiles/`。

可以用所提供的部署代码自行运行 Qwen，也可以连接考官提供的同协议公共服务；Qwen 服务不接触完整数据或真实状态。参考主轨迹关闭 thinking，使用 greedy decoding。对给出合法初始答案的案例，在生成该答案的同一可见历史上另外采样四次（temperature 0.7、top-p 0.9、top-k 40），供所有风险估计方法共用；采样中提出的工具调用不执行。所附参考 agent 初始阶段至多 20 次主调用，续跑后累计至多 32 次，这些是该 baseline 的配置，不限制考生选择其他后续求解方法。自部署的调用记录属于可复现材料，不能替代考官对模型执行过程的独立核验。

**baseline。** 风险估计包括模型自报概率、采样分歧、训练错误率，以及基于公开特征的监督估计和概率校准。策略包括不核验、全部转人工、按阈值转人工、按固定字段核验、核验当前路径上全部可达字段，以及基于公开证据的主动核验启发式。它们只使用公开输入、获准的观测、模型输出和训练池标签。

- 所附静态校准器绑定模型、提示词、输入整理规则、采样设置、调用上限、风险估计及公共协议实现，并绑定实际预算和费用。影响数据或预测的配置变化时须重新采集或拟合，不能误用旧产物；自行实现的在线方法可以更新参数并记录更新过程。
- 核验后的两个风险分别用公开的核验轨迹校准，且须与所用核验策略一致。实际新增查询之前检查后验校准器；零查询时沿用相应的事前估计，不要求凭空生成后验训练样本。未校准的自报 baseline 在核验前后都使用自报概率，单独比较。
- 转人工阈值在 `cal_select` 或 `dev` 上按实际错误代价选择，手动给定的阈值标为启发式。普通错误与严重错误的代价不同，单凭出错概率不能确定最优决策。
- 程序会报告全部转人工、风险取值过少等退化情况。主动核验 baseline 不声称计算了最优的信息价值。

**比较与解释。** 对同一固定初始 agent 比较风险估计时，共用考官的案例和初始轨迹，报告每种方法合法取得的新增证据和费用。允许跨题或在线方法时，风险预测时的信息可以不同，应记录案例顺序与学习过程；另做只使用固定历史的对照有助于解释收益。后续求解模型或算法可以变化，但不能把求解器变化带来的收益全部归因于风险估计。多个方法或后续模型共用一份测试证据账本，按模型列出的费用不能解释成各自独立取得信息的成本。

## 5. 评测

**主指标。** 每个模型分别计算，越低越好：

1. 核验前风险 \(p_i\) 在全部测试案例上的 Brier score \(B\)；
2. 交互案例上的平均决策损失 \(D\)。

两项都先在每个业务域内求均值，再对三个业务域等权平均。已经核验的题使用首次 oracle 前封存的 \(p_i\)，未核验题使用最后有效版本的 \(p_i\)，终局答案、\(q_i\)、\(r_i\) 使用最后有效版本。分母是服务固定的全部预期案例，漏交不会缩小分母。记 \(S_d\) 为业务域 \(d\) 的测试案例集合，则

\[
B=\frac13\sum_{d}\frac{1}{|S_d|}\sum_{i\in S_d}s_i,\qquad
s_i=\begin{cases}(p_i-e_i)^2,&p_i\text{ 有效},\\ 1,&\text{否则}.\end{cases}
\]

\((q_i,e_i)\) 和 \((r_i,f_i)\) 按同样方式在交互案例上计算并报告。服务拒绝非有限或超出 \([0,1]\) 的概率。

**有效性。** \(p_i\) 要求初始阶段为 `completed`，\(r_i\) 要求终局为 `completed`，\(q_i\) 要求两个阶段都为 `completed`。处于 `failed` 或 `missing` 的阶段，答案按错误计、风险按缺失计；初始阶段失败不影响已完成终局的单独评分。控制器无效时，三项风险都按缺失计。转人工后的人工处理结果不作为模型错误的标签。

**决策损失。** 记 \(c_i\) 为案例 \(i\) 已发生的全部工具和 oracle 费用，\(T_d\) 为业务域 \(d\) 的交互案例集合，则

\[
L_i=c_i+\begin{cases}
0.5,&\text{合法的 DEFER},\\
0,&\text{合法的 AUTO 且 } f_i=0,\\
1,&\text{合法的 AUTO 且发生普通错误},\\
5,&\text{严重错误、答案缺失或终局不合法},
\end{cases}
\qquad
D=\frac13\sum_{d}\frac{1}{|T_d|}\sum_{i\in T_d}L_i.
\]

严重错误指：危险品等级低估，包括把应为 `Unable to Decide` 的案例判为确定等级；把不具备放行条件的飞机判为 `aircraft_ready=true`；把尚未解决的客服问题判为 `RESOLVED`。模型失败时可以按协议提交状态为 `failed` 的 DEFER，损失为 \(c_i+0.5\)，\(r_i\) 按缺失计。控制器无效时损失为 \(c_i+5\)，不能通过转人工消除。

**辅助指标。** 以下指标只使用有效概率，并同时报告有效提交比例（NLL 除外，它按全部案例计算）。

- NLL：二元对数损失，有效概率截断到 \([10^{-6},1-10^{-6}]\)，缺失项记为 \(-\log 10^{-6}\)。
- ECE 与 aECE：预测风险与实际错误率之差的分箱加权平均。ECE 用 10 个等宽箱；aECE 按样本数自适应分箱，相同概率不拆到不同箱。
- AP：以错误为正类，衡量高风险排序能否优先找出错误；相同风险成组处理，没有正类时记为未定义。
- AURC：按风险从低到高逐步纳入案例，对各覆盖率下的错误率取平均；相同风险的案例按随机顺序取期望。
- 自动处理覆盖率、自动处理错误率、转人工比例和平均核验费用，用于解释决策损失。

**区间与反馈。** 主指标附 95% bootstrap 分位数区间：在每个业务域内按案例重抽样，重复 2000 次。该区间只描述这批案例的抽样不确定性，不保证分布变化下的表现。五次正式提交都只确认收件，不返回分数、错误率或任何与标签相关的指标。所有考生交卷或考试截止后，考官统一公布成绩，并永久关闭本场考试的报名和修改；已公布的测试数据不能再用于下一批考生。验证集允许即时评估，成绩不参与正式排名。报告正式成绩时，初始准确率、自动处理覆盖率和业务损失须与风险分数一起给出，不能只凭某一项 Brier score 判断模型的业务能力。

## 6. Technical report

报告围绕以下三个递进问题展开，附主要结果、必要的消融和复现入口。

1. **能否可靠识别模型可能出错的案例？** 固定基础 agent，比较自报概率、采样分歧和你提出的风险估计方法。说明训练、校准和选择数据的分工；报告概率误差、校准和排序表现，并用训练池案例解释"高置信错误"和"低置信正确"的成因，讨论估计在观测条件偏移时是否仍然可靠。

2. **新增证据如何改变对错误的判断？** 研究核验哪项事实、何时核验以及何时停止。区分对初始答案风险的更新与最终答案的变化，并与不核验、固定核验和核验全部可达字段比较。在相同预算下做消融，分析同一来源的重复读数、采样时间和核验顺序对结论的影响；不要把更多调用直接等同于更多信息。

3. **如何在错误、核验和转人工之间做出可解释的取舍？** 将风险估计接入完整策略，与阈值转人工和全部转人工比较，报告决策损失、覆盖率和费用。在开发数据上分析成本变化、预算限制和失效案例，说明改进来自更准确的风险估计、有效的核验，还是更保守的转人工，并给出适用条件、局限和复现所需的配置。

公开报告只使用训练池标签和获准公布的测试汇总结果，不附测试核验真值的汇总、服务凭证或其他参加者的运行材料。
